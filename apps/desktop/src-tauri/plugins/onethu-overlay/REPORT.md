## 实现了什么（对应需求 5）

- **浮在其他应用上层**：`SYSTEM_ALERT_WINDOW` appop 判定（`Settings.canDrawOverlays`）+ 引导页（`ACTION_MANAGE_OVERLAY_PERMISSION`）；`TYPE_APPLICATION_OVERLAY`（API<26 退 `TYPE_PHONE`）+ 前台服务承载，窗口生命周期与 app 进程解耦——OneTHU 在后台时悬浮层照常显示。
- **球可拖动 + 吸附**：52dp 雾面圆球，拖动实时 `updateViewLayout`，松手 180ms 动画吸附最近左右边框并写 SharedPreferences；重启/自恢复后回原位。
- **tap → 半屏面板**：原生立即就地展开（不等 JS 往返；后台 JS 被限流也不会点了没反应），面板 = 雾面卡片（头部 OH / 收起 / 本次关闭 + 可滚动消息区 + 底部「点击输入，长按说话」输入行 + 发送/长按说话按钮），底部滑入动画 220ms。
- **长按 → 语音输入条**：球按住 ≥450ms（`HOLD_MS=450` 与前端一致）→ 抖一下 + 变全宽 56dp 条（点点波纹随电平跳动 + 实时转写），抬手 emit `release`；条带 30s 看门狗（抬手事件丢失也不至于永远占麦）。
- **红线**：插件/服务/通知任何路径都不启动 Activity、不拉主窗口。通知点击只切球↔面板、「本次关闭」只关悬浮层；对话与消息全部在悬浮层内完成。
- **「本次关闭悬浮球」**：面板按钮 / 通知动作 → `OverlayPrefs.closedByUser=true, enabled=false` + 停服务 + emit `closed`（前端 `GlobalOrb` 已把 `closed` → `setOverlayClosedByUser(true)`，与 `lib/overlay.ts` 的 localStorage 语义对齐）。重新开启只能回本体点「打开悬浮球」（`overlay_show` 会清两个标记）。
- **事件**：`tap / hold / release / drag / submit(带 text) / closed`，带单调 id；主通道是原生直接对宿主 WebView 求值 `window.__onethuOverlayEvent(json)`（不走定时器，后台不被限流），兜底 1.5s 轮询 `overlay_poll_event(since)` + `overlay_ack_events`，TTL 6s（避免回前台重放陈旧手势）。

## 可行性判定（结论 + 理由）

1. **系统悬浮窗链路可行**。路径唯一且成熟：appop + FGS + `WindowManager.addView(TYPE_APPLICATION_OVERLAY)`。低门槛但有两个真机变量（见「真机才能验证」）：荣耀省电策略、overlay 窗口的输入法行为。
2. **面板内容选 (b) 原生 Kotlin UI**（否决 (a) 内嵌 WebView 复用前端）：
   - Tauri 的 IPC 绑在 **Rust 管理的那个 WebView** 上（`window.__TAURI_INTERNALS__` 注入 + 该 webview 的 IPC handler）。插件自建 WebView 拿不到；Tauri 移动端是单窗口模型，也无法把 Tauri webview 挂进 overlay 窗口。自己实现 loopback HTTP + Tauri IPC 派发既要用新依赖（禁），又没有公开 API 能把 invoke 派发到已有命令。
   - 更要命的是：**webview 是 OH 对话的必需一环**。`src-tauri/src/harness_embed.rs`：Android 上 OH 是内嵌 agent，其 `Host::call`（onethu.call 数据面）经 Tauri 事件 `plugin-rpc` 转给 webview 门面执行（`http_request` / `storage` 都在 JS 侧），`BRIDGE_TIMEOUT=15s`，webview 不应答就失败。→ 就算把前端塞进 WebView，也依然要另一个「活着的 webview」来跑对话，WebView 方案净亏。
   - 代价：视觉要手搓（跨应用模糊第三方拿不到，见下），动画只有 ValueAnimator 级别；收益：零额外渲染进程、零 assets 合并、IME/拖动/吸附直接可控、APK 不涨。
3. **Rust 侧没有可直接调用的 OH 对话命令**（Lead 点名要的调查结论）：
   - 前端入口 `askOh()`（`src/im/oh.ts`）→ `callRust("onethu.harness","run",{command:"chat",input})` → 桌面 sidecar / Android 内嵌 `harness_start`；应答 `{answer,error,confirm}`。
   - 内嵌实现 `src/harness_embed.rs`：agent 线程 ↔ 桥线程 ↔ **webview 门面**（`plugin-rpc` 事件）。数据面（HTTP/存储）没有 Rust 版实现。
   - ⇒ **不存在可复用的 Rust chat 命令**。若将来想让原生**独立**跑对话，需要 Lead 在主 crate 提供「不依赖 webview」的 chat 通道（=把 façade 的 http_request/storage 在 Rust 里再实现一份）。本轮不做，也不改别人文件。
   - 因此本轮落地为：**原生壳 + 前端脑**（GlobalOrb 继续用 `askOh`；原生面板内容靠 `overlay_push_ui` 回推渲染）。这需要 Lead 的两处接线（见下）。
4. **保活策略（已写进代码）**：
   - **FGS 类型 `specialUse`**（无每日额度；Manifest 带 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE=global_overlay_ball`）。**刻意不用 `dataSync`**（本仓库曾因它超限崩）。另声明 `microphone` 仅在需要时叠加。
   - **通知**：渠道 `onethu_overlay`（IMPORTANCE_LOW、无声音、不显角标），通知 id 4712，常驻；点击=切球/面板（**不拉 app**），动作=「本次关闭」。
   - **被杀后的恢复入口三条**：① `START_STICKY`（系统重建服务 → `onStartCommand(null)` → 按 prefs 恢复）；② 自杀前/`onTaskRemoved` 排 20s 自救闹钟（`ACTION_RESTART` → `OverlayBootReceiver`）；③ `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED`。三条都以 `OverlayPrefs.shouldAutoRestore()`（enabled && !closedByUser）为闸门。
   - **已知平台限制**：Android 15+（本机 Android 16 / targetSdk 36）**[移除了「持有 SYSTEM_ALERT_WINDOW 即可从后台启动前台服务」的豁免](https://developer.android.com/about/versions/15/behavior-changes-15)**，所以 ②（闹钟广播里 `startForegroundService`）在该机型上**可能被拒**；①③ 属系统豁免路径，成功率更高。全部 try/catch，失败不崩、不循环重排。
   - **「本次关闭」持久化位置**：原生 `SharedPreferences("onethu_overlay").closed_by_user`（+ `enabled` / `mode` / `ball_x` / `ball_y`）；与前端 `lib/overlay.ts` 的 localStorage `onethu.overlay.closed` 双写同步（原生自发的关闭会 emit `closed`，前端据此置 localStorage；本体里 `overlay_show()` 会把两边一起清掉）。
5. **后台上层真实模糊做不到**：第三方拿不到跨窗口实时模糊。代码里对 Android 12+ 用反射申请 `setBlurBehindRadius` + `FLAG_BLUR_BEHIND`（`isCrossWindowBlurEnabled()` 为 true 时），失败自动去掉该标志重试，绝不让悬浮层因此完全不出现；雾面观感由半透明底 + 1dp 描边 + 22dp 圆角兜底。

## 风险与未做

- **原生面板内容依赖前端 `overlay_push_ui`**：C 段接线未做时，面板只有「本地回显的用户气泡 + 占位文案」，OH 回复不可见（语音/打字事件仍会正常到前端并触发 `askOh`）。
- **`submit` 尚未进 `overlay.ts` 的联合类型**：现在靠 `as unknown as OverlayEvent` 投递；类型放宽后就自然了。

- **附件入口（需求 6-8）未做**：属 wave 2（ball-attach），原生面板未放入口；语音条内的附件按钮也留白。
- **未跑任何构建**（禁）；Kotlin 仍有编译失败的可能，风险点集中在：`startForeground(3 参)` 的 `types` 常量、`@TauriPlugin(Permission(...))` 写法（照抄 onethu-mobile）、`ContextThemeWrapper` 建 View 的兼容性。第一次 `gradlew :tauri-plugin-onethu-overlay:compileDebugKotlin` 的报错请直接回给我，我改。
