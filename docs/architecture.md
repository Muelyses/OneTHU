# 系统架构（0.11）

中文 · [English](en/architecture.md)

当前架构以 `dev3` 源码为准；历史计划见 [文档清单](documentation-catalog.md)。本说明不把规划能力视作已实现。

## 层次

```text
React 页面 / 三模式壳 / OH 胶囊
    ├── OneGUI 组件、令牌、主题、动效
    ├── explorer 状态、白板、原子、暂存箱、组织
    ├── 插件权限门面 → 宿主 API / 校园客户端
    └── Tauri IPC → Rust 网络、凭据、文件、Agent 与受限技能运行
                         └── OneTHU Harness（独立 Rust 子模块）
```

`apps/desktop` 同时承载桌面与 Android 应用。浏览器预览没有全部原生能力。`packages/core` 处理校园服务，`packages/gui` 是视觉与交互组件的真源；不要在业务页面复制一套主题系统。

## 身份、请求与数据

统一认证会话被服务客户端复用；云盘、GitLab、邮箱、日历与模型服务可能需要独立配置或授权。会话过期和二次验证不是普通网络重试：登录链路需要保留挑战上下文，避免刷新创建新的指纹、重复验证或无限重放。信任因子过多属于学校账户状态，不能靠盲目重试解决。

服务数据进入共享状态后供列表、日程与首页组件使用；三模式切换控制显示，不删除完整模式设置。作业截止不应只存在于完整模式，列表与时间轴要使用同一批可用作业数据。学校返回的错误详情可以保持原文；应用自产状态与错误需要延迟到渲染时本地化。

## 扩展与执行

插件经 `types.ts` 定义、`facade.ts` 注入。生成清单见 [API](api-surface.md)。36 个命名空间、255 个方法入口是当前源快照，不是跨版本不变承诺；权限必须由宿主检查，隐藏按钮不是安全边界。

OH 使用独立 Harness 子模块与宿主工具通信。极简/实用模式保留搜索、自填 API 与微信/飞书入口；完整插件与高级工具按模式和权限开放。清小搭服务、技能广场和本地 QuickJS 有不同的信任与执行边界，见 [OH 与清小搭](oh-and-xiaoda.md)。

## 暂存与跨设备

统一拖动会话区分点击、长按提起、自由移动、目标收纳。可收纳来源必须显式接入，见 [支持范围](sharing-and-organizations.md)。短口令依赖在线内容取回，不能承诺离线传输任意对象。NFC 目前不稳定，优先使用口令。

个人名片、好友、组织及相关文件依赖账户归属确认与远端同步。可合并修改优先合并，真实互斥冲突要求用户选择；错误的资料库归属不能通过自动新建大量空库绕过。组织权限需远端同步、前端检查和操作结果一致；暂无双真实账号的联调结论不能写成已验收。

## 验证边界

应用前端开发热重载与安装后的生产热更新不是一回事；当前不承诺动态下发原生可执行代码或生产补丁。平台原生差异、校方服务异常和模型配额应明确呈现。诊断与排障见 [隐私说明](privacy-and-troubleshooting.md)，公开素材来源见 [截图说明](screenshots.md)。
