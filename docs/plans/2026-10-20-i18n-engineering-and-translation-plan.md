## 建议采用的交接契约

优先沿用 PR 的扁平词典形式，减少迁移变量。工程负责人负责首次迁移、提取、键命名、格式支持和中文事实源；翻译模型只修改指定目标语言的字符串值。

计划中的文件职责：

| 文件 | 编辑者 | 约束 |
| --- | --- | --- |
| `apps/desktop/src/i18n/locales/zh-CN.ts` | 工程/产品 | 中文事实源；完整表达，不能留“第/周”“年/月”等跨键拼句 |
| `apps/desktop/src/i18n/locales/en-US.ts` 及明确授权的其他语言文件 | 翻译模型 | 仅改本批允许的 `messages` 值；键、结构、导入、导出不变 |
| `apps/desktop/src/i18n/index.ts`、`types.ts`、组件与业务源码 | 工程 | locale、订阅、格式化、消息参数、展示接入；不交给翻译模型修 |
| `docs/i18n/catalog.json`、`docs/i18n/batches/*.json` | 工程生成，只读交接资料 | 用途、调用位置、中文、参数/槽位说明、术语、长度提示、批次键清单、源文 hash |
| `tools/i18n-test.mjs` 及浏览器回归 | 工程/QA | 真实缺键、参数、语法、变更文件白名单、批次完成度与行为验收 |

这些目标文件目前大多不存在；上表是工程交付约定，不是已经可执行的工具清单。首次承接时先冻结一份工程基线 commit；后续新增中文需要重新生成对应批次，不允许翻译模型自行修调用或增加键。

目标词典格式与 PR 兼容：

```ts
import type { LocaleDef } from "../types.js";

const enUS: LocaleDef = {
  label: "English",
  messages: {
    "calendar.sync.failed": "Sync failed: {reason}",
    "calendar.auto.stopped": "Automatic sync stopped. Existing calendars and events are kept.",
  },
};
export default enUS;
```

示例键用于说明目标格式，不代表当前已有调用。词典必须保持纯静态数据：只允许普通字符串属性，不加入函数、计算属性、spread、运行时代码、模板插值或额外 import。验证器必须先用 AST 检查结构和重复键，再加载词典，不能运行后才发现同名属性被覆盖。

## 工程前置：按依赖顺序完成

### P0：从最新实现接入基础设施

1. 保留当前修复，只逐块借用 PR 的 runtime/词典参考；不整文件 cherry-pick 旧 `ChatDock`、Learn、导览、Vault、组织或 Schedule。
2. 三模式共用基础语言入口，更新每个窗口的 `document.lang`；语言持久化失效或存储不可用时有明确回落。跨窗口立即切换的产品契约应一致，并通过 storage/native 通知实测。
3. 真正消费文案的组件订阅 locale。禁止用 `key={locale}` 重挂整个应用；切语言必须保留表单输入、选中课程、聊天草稿、窗口与完整模式存档。
4. OneGUI 通过自身 provider 或可注入文案接语言，不能反向导入 desktop 的 i18n。当前 `packages/gui/src/components/form.tsx` 的搜索/清空/数值加减/上下限，以及 `display.tsx` 的加载、分页、面包屑、复制状态，都有中文默认值；仅扫描 desktop 会漏掉这些可访问性文案。

### P1：完整消息与可重渲染描述符

- `FormModalHost`、`ConfirmHost` 与 `App` 在 `main.tsx:120–122` 是兄弟节点。宿主订阅 locale 是必要条件，但还不够：当前 pending 存的 `msg/title/fields.label` 是已求值字符串。应用自己的长寿命提示应存 `{ key, params }` 之类的消息描述符，在渲染时解析；插件/用户传入的原文仍可作为普通字符串显示。
- 确认预设、导航/标签、搜索结果、tooltip、aria、缓存菜单项统一保存稳定键或描述符，避免在模块初始化或打开弹层时永久冻结译文。不要翻用户自定义工作区名、文件名、课程标题。
- 错误态区分应用自身的错误码/消息与服务器原始错误。应用错误优先使用稳定 code + 参数，由展示层翻译；服务端正文可以原样作为 `{reason}`。不可通过比较翻译后的错误句来分支，也不可把旧存档字符串全局替换。
- 每条可见表达完整提取：例如“同步失败：{reason}”“Week {week}”“{course} · {count} pending assignments”。不能让翻译模型靠前后空格或分别翻标点来挽救拼句。

### P2：先实现有限、明确的格式能力

为小模型减少歧义，第一轮建议保留普通 `{name}` 具名插值，不增加尚未实现的 ICU 语法。

| 场景 | 工程先提供 | 翻译模型规则 |
| --- | --- | --- |
| 普通插值 | 类型化 key/params；缺参数开发态失败或明确报警；`tOr` fallback 也按同一规则处理 | 占位符名字、大小写、数量原样保留，可在完整句中换顺序 |
| 复数 | 单独的复数 helper，用 `Intl.PluralRules(locale)` 选择预先登记的 `.one/.other` 等分支；需要“无文件”时显式 `.zero`；其他语言的类别由工程预建 | 仅翻已有分支，不写 `{count, plural, ...}`，不加删类别。0/1/2/大数都提供上下文 |
| 富文本 | 安全的命名 React 槽位 helper，例如完整消息 `Open {settingsLink} to configure sync.`；链接节点和链接文字另有稳定 key，正文按文本节点渲染 | 保留指定槽位；不写 HTML/JSX/Markdown，不增加 href，不使用 `dangerouslySetInnerHTML` |
| 日期、时间、数量、金额 | 统一 `Intl.DateTimeFormat/NumberFormat`，使用 UI locale 显示；学校时间计算保持 Asia/Shanghai；协议传输仍使用原 ISO/epoch | 不翻日期格式字符串、货币代码、时区或 API 日期 key；可移动已经格式化的 `{date}`/`{amount}` |
| 换行、引号、快捷键 | 中文事实源与元数据先规定是否可换行/是否多段；快捷键以参数或只读字面量传入 | 保留必需换行及变量；不要将中文句子里的引号留在业务源码两侧 |

如果工程负责人决定统一用 ICU MessageFormat，必须先接完整解析器、格式化与富文本白名单测试，并同步改本指南和样例。**只能选一种已验证契约**，不能一部分词典写 ICU、运行时仍只有正则替换。翻译模型不负责选择或实现消息引擎。

### P3：建立能阻止错误的护栏

工程门槛不是旧脚本 exit 0，而是以下错误注入必须可靠失败：

1. 静态 key 不存在；动态导航注册项少 name/note；漏掉 `tour.*`、`misc.*`、`tOr`；误把颜色函数 `t("primary")` 当翻译调用。
2. 译文丢 `{name}`、改名、重复槽位、空字符串、值不是 string、重复属性、插入执行代码。
3. 本批 key 漏翻、越批改动、目标语言多出不存在的键、修改了中文/运行时/业务/测试文件。
4. 源文 hash 已变，但旧译文仍被当成已审定；新枚举/动态键族缺分支。
5. 第三语言在 Node 测试有、Vite 构建没有；语言持久化了却未能注册；文档 lang 与界面语言不符。

批次覆盖按本批有效 key 计算。品牌名、缩写、URL 等允许中英文相同的值由工程元数据明确列出；不能靠“目标文件所有 key 都存在”或“中文 grep 为零”宣称完成。英文文件可以预置中文待译值，但这些值必须在批次清单中保持待译状态。

## 何时可以交给小模型

工程完成对应模块的提取与验证后即可按模块交付，不必等全站每一页都准备完；但每个交付批次必须满足：

- 最新工程基线可启动，词典文件已存在；该模块没有依赖小模型修改源码才能正确表达的拼句。
- 提供只读批次 JSON：目标语言/文件、允许键、源文及 hash、用途、参数类型和含义、复数/槽位归属、术语、字符数建议、当前界面截图或位置。
- 动作短标签与无障碍完整名称分开说明；“删除记录”和“撤销分享”等相似词给后果上下文，不按中文重复值机械合并。
- 入口和消费组件实时响应语言切换；已有回归验证业务 id、输入草稿和数据未变化。
- 本批校验命令已经落盘、可以独立运行，且错误注入证明确实会失败。

小模型批量建议：先交 30–60 个短消息验证质量；复杂计数、危险确认、连接错误每批 15–30 条。不同模型/批次不要同时改同一目标词典文件；需要并行时工程先拆分领域文件并收口注册，不让模型自己拆目录。

可沿用深审报告的领域顺序：壳与三模式导航 → 学习/日程/本轮同步 → 暂存箱与分享 → 组织 → OH/连接 → 校园服务与存储 → 高级设置/导览/画廊。每批只检查该批定义的完成度，最终再对发布语言执行全覆盖门槛。

以下模板只有在工程前置完成、占位内容由负责人填实之后才能发出：

>
> 先读批次上下文与术语表。逐条翻译完整表达，保留具名占位符和 React 槽位，按已存在的复数分支分别翻译。仅允许 `{name}` 格式，不得添加 ICU、HTML、JSX、Markdown 或执行代码。保持动作与状态准确，尤其生成≠复制、取用≠删除、撤销≠删除记录、已保存≠已同步。

> 原始课程名、作业/文件/邮件/组织内容、品牌、URL、标识符、安全载荷和协议值不翻。不要为缩短文本删去权限限制、数据保留范围、危险后果或失败状态。标签用简短动作；读屏名称必须完整易懂。

## 验收命令与全量质量审查

当前可核验的 PR 旧命令只可在其独立副本运行：

```sh
node --import ./tools/ts-resolve-register.mjs tools/i18n-test.mjs
```

**待工程实现**的同名新版脚本应支持 `--locale` 与只读 `--batch`，例如：

```sh
node --import ./tools/ts-resolve-register.mjs tools/i18n-test.mjs \
  --locale en-US --batch docs/i18n/batches/shell-en-US.json
```

当前 exp 不存在这个新版脚本/参数，不应让翻译模型现在执行或自行补实现。其退出码需要同时覆盖词典语法、该批完成度、参数、源文版本与文件/键白名单；全局扫描由负责人另跑。每批合入前至少执行新版 i18n 护栏、desktop typecheck/build；最终加 `pnpm guard` 与 `pnpm guard:onegui`。

全量质量审查由工程/QA执行，不能用翻译模型自评替代：

1. 三模式 × zh-CN/en-US × 320/390/844 横屏/1280，检查长字符串、200% 字体、焦点返回、aria/tooltip/placeholder/状态播报和窄屏布局。
2. 真组件测试已打开的菜单、确认、表单、搜索、课程页与 OH 来回切语言；草稿/选项保留，所有应用文案及时刷新，用户原文不变。
3. 0/1/2/大数量、非法/缺失日期、校园跨午夜、加载/失败/重试；语言只改变显示，不改时间计算、路由、权限、请求或数据存档。
4. 按最新源代码执行领域回归；当前日历/邮箱已有 `system-calendar-state-test`、`cloud-calendar-test`、`calendar-draft-test`、`schedule-homework-test`、`mail-state-test` 等，不可为译文改名删掉这些行为断言。浏览器定位逐步用稳定语义标记，同时独立检查该语言的可见文案。
5. 导览实屏图需要英文版本时，从真正英文界面重新捕获；小模型不能手绘或拼一套假的英文截图。第三方网页、原始邮件、模型回答和用户内容不是“剩余中文漏翻”。
6. 全仓残留通过 AST 分类为待提取 UI、协议/比较值、原始内容、示例数据、诊断日志或注释；逐类处理，不能以无中文作为完成条件。统计并报告发布语言覆盖、批准同文项、未提取 UI 和未测场景。
