# 三种模式的空间导览与交互演示

2026-10-20 · exp · 起点 98eb32f0

## 目标与设计

将说明卡片改为可亲手操作的空间演示。文字和真实功能按钮稳定可读，立体感来自卡片边缘、景深、光面和收拢/展开的空间关系。采用 CSS 3D 与有限时长的过渡；不引入 WebGL，也不做持续旋转文字的背景动画。继续复用 OneGUI 色彩、尺寸与动态偏好。

- 极简模式：今天、五个入口，共两课。
- 实用模式：今天、更多功能、调整四个入口，共三课。
- 完整模式：白板、暂存箱、口令、碰一碰、组织，共五课；其他六个主题在结束页按需探索。
- 模式选择保留原有准确描述，切换只改变展示，不重置已有数据与设置。
- 演示仅改变本地演示状态；真实功能按钮直达对应页面。结束页扫码连接仍可跳过，OH MCP 仍仅在完整模式显示。
- 每个舞台有明确的演示操作、重放/暂停反馈；系统与应用减少动态效果时保持功能完整的静态呈现。

## 实施顺序

1. 抽出课程数据与导航，修正过时说明，保留全部旧落点。
2. 实现 TourIllustration 与 tour-scenes.css 的模式场景、五个核心场景和安全演示交互。
3. 重整 OnboardingTour、ExperienceModePicker 与独立 tour.css：稳定页脚、可返回步骤、可选探索、真实体验返回条和方向过渡。
4. 删除旧图示样式，接入 OneGUI 配方，检查短屏、窄屏和减少动态效果。
5. 更新并执行真实浏览器用例，实际查看桌面/手机截图，修正发现的问题后提交。

- 主 agent：导览壳、模式选择、样式整合与最终验收。
- gui_mobile：空间舞台及其 OneGUI 配方。
- audit_org_shares：课程内容、导航和静态契约。
- audit_latest：浏览器流程、动效与布局验收、前后截图。

检查 guard、桌面类型检查与构建；运行 onboarding-browser、experience-browser 和新的 onboarding-motion-browser 用例。覆盖 1280 桌面、390/320 手机和短横屏，三种模式、十一处真实落点、跳过/返回/快速切课、键盘焦点、模式数据保留、减少动态效果、深色与玻璃。截图必须人工查看，不能仅凭测试通过评价视觉质量。

性能采样只作本机 Chromium 参考，不宣称实体手机性能；本轮不把 NFC 演示等同于真实设备联调，不把组织演示等同于双账号验证。
