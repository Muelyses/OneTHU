# 登录二次认证页与登录前语言切换

## 现场和原因边界

Windows 0.11 的现场日志确认：OAuth 登录页 HTTP 200、17524 字符；SM2 凭据 POST 已提交，HTTP 200 返回 1661 字符，随后为 `unexpected-page / credential-entry`。这不是“请求未发出”，该摘要也不能证明密码错误或代理异常。

源码存在可复现的回归：学校 React 二次认证页面可能只有 `<title>二次认证</title>`，正文仅有挂载节点。新增的 `isFinishedIdEntry` 只读正文，漏掉标题，直接阻断后续 2FA。旧自有认证代码已记录这种学校页面形状。离线构造同形页面在修改前复现同一错误及一次凭据 POST。现场日志没有响应正文，不能声称那 1661 字符已被直接确认就是此页面；需 Windows 新包复测。

## 修改

- 登录和 ID 漫游统一识别可见标题与正文中的二次认证标记，支持 HTML 字符实体。不扫描脚本中的字串；密码表单、公钥表单或明确学校错误不能被标题误判成验证页。不重放密码，不增加自动重试。
- 登录、2FA 方式选择、验证码输入三处增加 OneGUI 语言选择，入口双语显示，选项来自现有语言注册表。位于表单上方正常文档流中，不采用遮挡内容的固定浮层。
- 复用全局语言偏好与持久化；切换保留账号、密码、方式、信任选项与验证码，不触发认证请求。
- 应用状态保留错误原因，在渲染时使用纯格式化函数本地化；错误诊断在捕获时记录。学校返回的外部错误详情保持原样。
- Android 对外仍 0.11.0，内部 versionCode 11003，沿用正式发布证书。

- 生产构建浏览器验收 103 项通过：桌面/手机、微信与 TOTP、语言即时切换、错误重译、保留输入、刷新持久化、320 像素窄屏无横向溢出；无浏览器运行时错误。
- info-lib 构建、desktop 类型检查、CSS、发布身份、Windows WebView 线程护栏、网络日志隐私 20 项通过；i18n 7552/7552、errors 0，无新增待翻译词条。
- 浏览器使用 macOS Chromium、模拟 Tauri IPC 与学校响应；不使用真实密码、不发送学校认证请求。这不等于 Windows WebView2 实机验收或真实会话长期稳定性验收。最终截图后，未实现的首页数据接口可能使模拟会话回到登录页。

## 后续：首次登录被退出与残留冷却

用户随后在 Windows 实测：首次进入后被送回登录页，20 秒后重试才成功。诊断显示学习页为 `id-login-link`；后续现场记录已经取回 79 条作业、27 条通知、61 个文件，说明不能将单个学习会话恢复问题作为整个主会话失效的结论。原浏览器验收仅断言瞬间离开登录界面，未覆盖随后的数据错误，这是验收缺口。

- 主认证链真正完成时，当前 attempt 的成功钩子清除该轮冷却；错误密码、未知认证页和受限请求仍保留节流。旧链晚完成不得清理新链的门禁。
- 校园数据、学习数据和学期列表恢复失败时显示服务自身错误，保留主界面；禁止在这些数据 hook 中直接 `backToLogin()`。
- 并发恢复先加入已有 Promise，再判断下一轮节流；避免第二个 hook 在第一个还在恢复时立即被判失败。
- 受信直登与新 2FA 共用学习会话准备逻辑，先完成同样的恢复再进入主界面。某学校服务不可用不被当成密码失败。
- 已安装宿主认证 hook 的 LearnClient 不得再绕到独立旧账密路径，避免越过统一门禁并打断已有 2FA；无宿主的独立客户端保留原路径。
- 现场日志暴露出 URL 矩阵参数仍可能带 Java 会话标识。JS 与 Rust 日志现在同时去掉普通及编码后的矩阵参数，不改实际请求地址。

新增验证：生产浏览器 117 项通过，覆盖受信直登、微信/TOTP、故意不提供学习会话、等待实际数据 hook 报错后仍保留主界面、成功冷却清空、不重放密码；恢复行为 7 项、门禁/指纹 28 项、认证行为 30 项、JS 隐私 23 项、Rust native_security 11 项通过。类型与生产构建通过。依然不能替代受影响 Windows 的真实校园账户验收。
