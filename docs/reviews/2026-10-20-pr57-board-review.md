# PR 57 白板部分审查与模板修复

审查对象：PR 57 第一提交 `9426f7fc382c225c6fbeea0859b0fe1bf569f60c`，对照本地 `exp` 基线 `f3ba4dd6`。不涉及后续 i18n 提交。未整体应用 PR，也未加入默认吸附。

## 结论

- 接纳并适配“恢复默认首页”确实应重置真实白板的修复。
- 不接纳默认启用、只能用 Alt 临时关闭的吸附；四列高密度首页也不作为默认布局。
- 另行修复现有三个旧模板的像素尺寸错误。保留首个默认首页，其他模板统一 1104px 基准、宽卡与纵向滚动。
- 已保存的自定义白板不自动重排。模板仅在用户明确套用时替换当前板；恢复默认只影响首页。

## PR 实际改变了什么

四列本身只是预设，不是持久化网格约束。PR 的 `boardCore.ts:339–359` 将默认 7 件组件变为 13 件，四列每列 264px；`migrateHomeCanvas` 的版本判断仍使已有 v2 白板保持原样。它没有把所有用户旧布局强行转成四列。

但拖动行为确实会改变。PR `FreeBoard.tsx:760–795` 每帧默认调用 `snapMove` / `snapResize`，只有 `ev.altKey` 才跳过。没有可见开关或手势说明，普通触屏和笔也不能按 Alt 临时解除。吸附半径按 `8 / displayScale` 换算，屏幕手感尺度一致，但这是持续改变落点的默认规则，不符合当前自由拖动方向。

候选边线来自所有组件，未限制另一轴距离或可见范围（`boardSnap.ts:80–105`）。独立运行该提交的纯函数：处于 `(104,20)` 的卡会被 `y=5000` 的离屏卡拉到 `x=100`，并给出跨越 5080px 的参考线。即使未来提供可选吸附，也应先解决这一点。

## 可复现缺陷

### P2：西/北缩放吸附在最小尺寸处移动了对侧边

位置：PR `apps/desktop/src/state/boardSnap.ts:133–150`。

输入矩形 `(x=100,y=100,w=120,h=64)`、`minW=120,minH=64`：

- 西边吸到 `x=105` 后，宽仍被夹到 120，右边从 220 变为 225。
- 北边吸到 `y=105` 后，高仍被夹到 64，底边从 164 变为 169。

与其“只移动正在拖的边、对侧不动”的契约相反。应限制候选边到 `right-minW` / `bottom-minH`，无法满足最小尺寸的候选不吸附。该纯函数缺陷已通过读取指定 Git 提交并实际执行复现，结果在 `/tmp/onethu-pr57-board-snap-repro.json`；没有修改运行中的生产源码来复现。

### 不应覆盖当前暂存箱接管修复

PR 的 `FreeBoard.tsx:802–819` 在 pointerup 和 pointercancel 共用提交路径，只要 `liveRef` 存在就落库；`onMove` 也只看瞬时 `gestureOwner()`。当前分支已将接管锁存在整个按压会话：一旦暂存箱接管就清除 live，此次不再移动或缩放原组件。不能用 PR 文件覆盖当前实现，否则会回到“已绿色命中但白板仍移动”的旧边界。未来若单独加入参考线，也要在接管/取消时清理它们。

## 当前三个模板为什么挤

基线 `boardTemplates.ts:33–58` 的今日/学习/极简仍用旧四格布局，`boardCore.ts:169–176` 将其换成主卡 286px、侧栏 90px。基线 `FreeBoard.tsx:834–837` 又统一转 `rectFromCell` 并标成 `manual:true`。与此同时桌面 100% 的窗口适配宽度至少是 1104px，所以 Mac 宽窗口也只在左侧挤成一小列；放大屏幕没有解决作者尺寸本身错误。

PR 只更换默认首页，没有修改这条模板应用路径；新增四列里的通知/作业仅 264×116px，也不能解决这些列表的阅读问题。

## 本轮适配实现

- `boardTemplates.ts`：模板保存原生 `rect`，派生的 `cell` 只保留插件/OH 兼容契约。今日与学习主卡宽 540px，列表高 392–480px；极简为 1104px 标题、740px 课程和 340px 余额。组件间距至少 24px。每次生成独立数据对象。
- `FreeBoard.tsx`：应用模板直接保留 rect 与尺寸归属。未固定尺寸的模板允许原有按内容拟合；用户手动改变大小后仍由原 `withRect` 接管。显式应用模板才恢复当前 100% 和 1104px 参考宽度，不改变日常拖动/缩放策略。
- `board.ts` / `Settings.tsx`：恢复默认重建首页两朝向的真实组件，清旧布局偏好并阻止旧自由板延迟回灌。所有用户 OnePage、活动板和排序偏好保留。首页各视图倍率归 100%，专用事件使已挂载的首页同步重设参考宽度；普通保存不会触发。

没有加入吸附，没有调整现有用户组件位置，没有修改首页版本迁移或原 7 件默认布局。
