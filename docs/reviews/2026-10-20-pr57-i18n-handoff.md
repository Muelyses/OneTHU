### E1：仅订阅 App 不能保证已挂载界面跟随切换（已最小复现）

证据：

- `apps/desktop/src/App.tsx:171` 在 App 中调用 `useLocale()`，注释将其解释为整棵树刷新。
- `apps/desktop/src/main.tsx:120` 的 `App`、`ConfirmHost`、`FormModalHost` 是同级节点。
- `apps/desktop/src/lib/formModal.tsx:36` 只订阅表单 pending store，按钮在 `:81`、`:87` 调用非订阅的 `i18n`。
- `apps/desktop/src/lib/confirm.tsx:133` 的 PromptHost 只订阅 prompt pending store，按钮在 `:159`、`:160` 调用非订阅的 `i18n`。
- `apps/desktop/src/i18n/index.ts:116` 的 `useT` 才会建立 locale 订阅；直接导入 `t` 不会。

最小复现使用 PR 的真 `FormModalHost`、`ConfirmHost` 和 i18n runtime，保持 `main.tsx` 的同级树形；React/ReactDOM/Chromium 真实运行，OneGUI 外壳替换为简单 DOM 组件，避免加载业务。仅在临时探针中给四个原本未翻译的按钮补 `Cancel/Submit/OK`，用于排除“词典没有英文”的干扰：

```text
切换前按钮：取消、提交、取消、确定
调用 setLocale("en-US") 后：
  App 订阅值 = en-US
  t("auto.lib.formModal.1") = Cancel
  已挂载按钮 = 取消、提交、取消、确定
```

探针自然退出 0。它证明宿主没有随 locale 通知更新；不代表真实用户能在所有模态打开时点击到底下的设置。后续跨窗口/程序化切换同样不应依赖任意业务事件碰巧刷新。

最小修复要求：让实际文案消费组件或公共宿主订阅 locale；仅对已解析的文案缓存把 locale 纳入依赖。不要通过给 App 整体加 `key={locale}` 重挂来修，这会重置未提交表单、聊天和页面状态。已存用户内容不得在切语言时翻译或改写。

模块常量审查的准确结论：本次未找到明确的顶层 `t/i18n` 直接求值实例；`NAV_REGISTRY` 使用键/渲染时解析是正确方向（`state/navigation.ts:155`），`PAGE_TITLES` 也已保存键（`state/explorer.ts:229`）。不要把“所有模块常量被冻结”写成已证实缺陷。仍需单独检查 `TabHost.tsx:256` 的 `useMemo([st.tabs])` 内首页标题、`GlobalOrb.tsx:152` 的 memo 组件以及独立窗口。`useCallback` 内在点击时调用 `t()` 会读到当前语言，**不能仅凭 callback 没有 locale 依赖就判为旧译文**；DockMsgList 的父级也有新函数 props，不能未经复现认定被 memo 阻断。

### E2：缺键与格式护栏有可复现漏检（批量翻译前必修）

证据：`tools/i18n-test.mjs:42` 明确允许局部译文，`:84` 的扫描只认若干命名空间、双引号调用和几种固定字符串形态；`navreg.*` 由 `state/navigation.ts:162` 动态生成。`misc.*`、`tour.*` 的调用不在该 NS 正则里；`tOr` 也不被调用扫描覆盖。文件头 `tools/i18n-test.mjs:7`、类型注释 `i18n/types.ts:5` 仍声称逐语言全键一致，与实际策略矛盾。

在临时副本逐一故障注入、每次恢复原文件后，以下三项 **全部仍然自然退出 0**：

1. 把 `en-US` 的 `shell.addToHome` 从 `Add {name} to home` 改为 `Add to home`。
2. 从两张词典同时删除静态引用的 `tour.mcp.aria`。
3. 从中文词典删除动态引用的 `navreg.learn.name`。

第一项丢失必要对象名；第二项 UI 会显示原始键；第三项被中文 fallback 隐藏。它们没有被“all assertions passed”识别。

修复要求：

- 根据 i18n import 绑定和 `useT()` 变量做 AST 引用检查，不能把任意同名 `t()` 都当翻译函数。实际源码另有颜色函数 `t("primary")`，粗扫会误报。
- 明确枚举动态键族：注册表 id + `name/note`、PAGE/TAB/CATEGORY 键表等；测试新增一项但漏键时失败。
- 校验每个已提供译文的占位符名称集合、值类型、非空、重复属性、占位符调用参数。给稳定的 key/params 类型或生成类型。
- 区分“开发中允许回落”和“该语言发布完成”。开发可以部分翻译；发布清单指定的语言/批次应强制完整，不能一边宣称全键一致一边永久只打印覆盖率。
- 保留未知 locale 回落/拒绝、订阅、持久化测试；新增第三语言要在真正 Vite 构建中验证自动注册，Node 静态种子测试不等于这一项通过。

当前已有 9 个占位符键且无不一致，不应为制造问题随意改写。`tOr` 在键完全缺失时直接返回 fallback、不插值（`i18n/index.ts:107`）；`tOr("missing", "Hi {name}", {name:"A"})` 实测仍为 `Hi {name}`。当前导航调用没有传这种模板，故列为 API 合约缺口，不能报成现有导航已坏。

### E3：机械切片不能仅靠填英文词典解决（已由源码确认）

典型位置：

| PR 位置 | 当前形态 | 为什么翻译模型无法仅改值解决 |
| --- | --- | --- |
| `plugins/ChatDock.tsx:1004–1006`；中文键 `auto.plugins.ChatDock.13/.14/.15` 在词典 `:2355` | 前半句 + 查询词 + 后半句，另有硬编码中文引号 | 无法自由调整整句语序、引号和空格 |
| `pages/Schedule.tsx:1085` | 年数字 + “年”键 + 月数字 + “月”键 | 改两个单位仍不能得到自然英文月份顺序 |
| `pages/Schedule.tsx:1165` | “第” + 周数 + “周” | 需要完整 `Week {week}` 消息 |

| `components/explorer/PracticalFeatures.tsx:37` | 数量 + 独立单位键 | 需要 0/1/多项规则，不是所有语言都能追加同一单位 |

`i18n/index.ts:95` 当前只支持 `/\{(\w+)\}/` 替换，不支持 ICU plural/select。后续可选择引入成熟消息格式或实现明确的有限 plural 接口；选定后统一文档和测试，再翻计数消息。

### E4：日期、数字、页面语言与窗口同步未接通（静态确认，未做全窗口实机）

- `apps/desktop/index.html:2` 固定 `lang="zh-CN"`；`setLocale`（`i18n/index.ts:81`）只改内存、localStorage、通知订阅者，没有更新文档语言。读屏可能按中文发音规则处理英文。
- `pages/Schedule.tsx:691` 显式 `toLocaleTimeString("zh-CN", ...)`；`pages/Settings.tsx:510` 的 `toLocaleString()` 则走系统默认语言。二者都不由 UI locale 控制。
- 相同 runtime 没有 storage/native 语言同步订阅。独立悬浮窗使用另一份内存状态；是否跨窗立即生效应明确并实测，不能宣称已经实现。

修复要求：公共 `formatDate/formatTime/formatNumber/formatRelative` 接 UI locale；保持学校日期、课程周、提交截止时间的时区和计算语义不变。只改显示，不能把 locale 格式化结果写回 API 或日期 key。更新每个窗口的 `document.documentElement.lang`；若支持 RTL 再按配置处理 dir，不得将所有非中文一概设 RTL。语言码失效、存储不可用、重启与新开窗口都应有测试。

### E5：语言入口和导航词库不完整（可确定的可达性/一致性问题）

- 语言下拉只在完整设置 `pages/Settings.tsx:568`；`SettingsOverlay.tsx:34/:84` 对极简/实用渲染 `SimpleSettings`，其 `SimpleSettings.tsx:22–44` 没有语言入口。新用户选极简后，必须先切完整模式才能改语言。应把语言选择视为基础偏好，在三种模式的适当位置共用，不要为此恢复被隐藏的高级设置。

## 5. 给翻译模型的分批任务

## 6. 术语建议与文风约束

以下是交接用建议表，不冒充已经获得产品定稿。首次翻译前锁定一版，同一概念在按钮、搜索、标题与读屏中复用。

| --- | --- | --- |
