# 云盘自动连接恢复（2026-10-26）

## 现场

原 dev 的设备本地授权为 acknowledged/cloud/oh 全部 true，云盘配置文件不存在。学校 Learn 会话恢复成功；云盘的直连 profile 链连续落到 ID 登录表单，旧静默连接只处理 checkSingle，不处理已有学校登录但缺少直连 ID 会话的场景。当前证据不能确定此前是哪次登出移除了配置文件，因此没有把文件缺失归因于权限开关。

CLI 恢复路径还会用后台快照完整替换 native Cookie 仓；同账号在 GUI 中后来建立、而后台尚未收录的直连云盘会话会随替换丢失。

## 修补

- 静默连接先等待设备授权初始化及持久化云盘配置读取，避免把尚未加载当作未配置。
- 先验证已保存令牌，网络故障保留凭据；确认为 401/403 才尝试重新发现现有令牌。
- 多个启动入口共享一个连接流程。已登录的同账号可复用内存凭据与设备信任，最多续接一次直连认证；遇到二次认证返回提示，不循环提交。
- `InfoClient.ensureDirectIdLogin` 增加可选 `consumeServiceTicket`。云盘明确兑付本次认证产生的 OAuth 回调，再读取现有令牌；默认行为保持原状，TUOJ 等已有调用不变。仅建立 ID 会话、然后重新发起 profile，实测仍可回到登录表单。
- 每个异步阶段核对 native epoch、学校账号、云盘 credential version 和授权，阻止登出、换号后的旧响应重新接回。
- CLI 恢复只有在持久化 GUI 账号与已验证后台账号一致时，保留后台缺少的直连学校服务 Cookie。重叠 Cookie 与 WebVPN 控制 Cookie 以后台为准；换号、登出、未知归属均不合并。
- 未修改云盘授权和 CLI 的逐次确认策略；没有新建或删除云端资料库。
