# 雨课堂查询与微信回复恢复（2026-10-26）

## 故障与修补

### 雨课堂的假会话失效

桌面心跳和内容目录均能读取，而 SDK 的 `yuketang.*` 连续 HTTP401。SDK 学校传输层会丢弃显式 Cookie 头、从自己管理的 jar 重建 Cookie。新增查询桥把雨课堂 Cookie 放在请求头，却没有交给传输层的 Cookie 仓，因此有效配置也会被报为失效。

新查询使用一次操作专属的服务传输：继承调用方的测试/网络注入、超时与账号 epoch 门禁；在精确的 `https://pro.yuketang.cn` origin 将客户端头部凭据放入隔离 Cookie jar。结束时关闭并释放；账号轮换或关闭 Node runtime 时取消所有未结束的服务传输。雨课堂 Cookie 不进入学校主 jar，也不会被导出进桌面学校会话交接。

新增真实 Node Cookie 重建回归，模拟服务端要求携带 sessionid 和 uv_id，同时确认学校 jar 没有变化。

作业查询还修复：deadline=0 显示为空，避免出现 1970-01-01；提交状态读取失败时，查询返回 incomplete/issue，而不是把不确定结果伪装成确认未交。学校明确返回会话失效时继续抛出会话错误。

### 微信通道凭据被覆盖

`ImStorage.fileName()` 固定返回 `im.cfg`。原通道配置与新增的微信任务回复上下文各使用一个 ImStorage，但实际写入同一文件；二者使用不同的派生口令，收到消息保存上下文后覆盖通道凭据，重启便无法解密配置。

实证：现场 im.cfg 只能用任务上下文派生口令解密，内容只有 owner/recipient/contextToken/botId。独立 CLI 的通知配置也已没有微信凭据，不能凭上下文重建 botToken。该错误来自本地新增的上下文持久化实现。

修补：保留主配置的历史文件 im.cfg；其余存储按自己的 key 分配独立文件。读取失败保留原文件，记录 unreadable 状态；后台绑定同步遇到 unreadable 立即停止，避免把解密失败当作用户主动断开并删除后台配置。显式重新扫码保存后解除 unreadable。关键文件读写启用 strict，真实磁盘失败返回错误。

已将本机原密文备份到用户缓存目录，并把可恢复的加密上下文放到独立文件。用户重新扫码后，已确认通道配置可正确解密、微信启用且主人绑定存在；重启原 dev 后微信自动连接。

### “已有对话在运行”

该提示来自 Harness 的全局运行票。页面重载丢失了前端请求与停止入口时，旧工作线程仍可持票；此前前端 RPC 超时也没有向宿主发送本次请求的取消。

修补：已派发的 chat 按 runId 登记本窗口的停止回调；pagehide 发送定向取消。原生 invoke 在首次调用后缓存，窗口退出时可以立即入队 IPC。RPC 失败/超时也取消本次运行票，然后保留原始错误。完成后清理登记。继续保留真正互斥：取消标记不强行解锁；其他窗口的任务不会被新请求抢占。

### OH 错误声称雨课堂没有接入

微信恢复能回复之后，用户再次转述 OH 声称「已安装插件和技能没有雨课堂，所以不能查询」。实查当前运行的 Harness 二进制已包含 `query_yuketang`，两个内置清单也有 `exthw:read`。故障会话的轨迹却只有 `list_plugin_cmds/open_page`，以及随后重试的 `skills_search/ext_plugin_installed`，从未调用雨课堂查询。模型沿用了自己早前「未接入」的错误回答，把扩展目录误当作完整能力表。

补充系统能力纪律：内建雨课堂无需另装技能／插件，直接用 `query_yuketang`；当前工具及真实结果优先于历史能力判断。插件、技能、页面目录各自的搜索结果不能证明内建能力缺失，接口失败须按真实错误说明。

为明确的雨课堂读请求增加一次真实工具预读，先通过同一 `tools::execute → yuketang facade` 权限与账号门禁取得数据，再进入模型循环。作业请求读取既往及最大支持未来窗口（3660 天），结果保留 windowDays/complete/issues；泛化的再次查询只从人类消息追溯最近的具体任务。当前消息没有明确雨课堂读取意图时不触发，显式拒绝读取或文件问答边界也不触发。预读不安装插件、不改变权限、不提交作业。结果以完整的工具调用／回执配对进入上下文，真实失败原样保留；取消和模型失败恢复完整的历史与轨迹快照。

新增回归覆盖历史错误说法、重复重试、中文与英文作业请求、无关问候、拒绝读取、文件问答边界、真实宿主读取、权限拒绝及工具消息配对。
